## 1막 — 정체성: 거짓이 인프라가 되기까지

### 슬라이드 비트
1. **World's First 100% LLM OS.** MaruxOS는 LFS(Linux From Scratch) 12.x 계열 from-source 배포판. Public Domain. "오픈소스 환원" 이념. 설계·빌드·디버깅을 AI가 주도, 인간이 최종 결정.
2. **훅(hook) — 배신부터 던진다.** "이 프로젝트는 1년 가까이 자기 광고에 거짓말을 하고 있었다."
3. **6.12 → 6.7.4, 5개월(실측 약 1년)짜리 환각.** 1.x 전 시리즈가 문서·메타데이터에 **"Linux 6.12 LTS"**로 광고했지만, 실제 `vmlinuz`는 **6.7.4**였다.
   - Genesis(2025-12-14): 사용자 의도는 6.12였으나, 그 순간 이전 세대 AI가 `KERNEL_VERSION`을 6.7.4로 **환각(hallucinate)** 해 박았다. 그리고 진짜로 그 버전을 다운로드·컴파일·설치했다.
   - 2025-12-16 ~ 2026-02-19: **92회 빌드, 커널 재컴파일 0회.** 유저랜드(Firefox·ibus·idesk·폰트)만 매번 바뀌고, 환각 커널은 단 한 번도 다시 건드려지지 않은 채 인프라의 기반이 되었다.
   - 발견: 2026-05-05.
4. **왜 살아남았나 — 핵심 교훈 선(先) 제시.** `KERNEL_VERSION` 값은 어디에서도 실제 `vmlinuz`와 비교·강제되지 않았다. 표면(neofetch, `/etc/os-release`)은 깔끔했다. **표면 검증만으로는 진실에 닿지 못한다.**
5. **2.0.0의 의미.** 2.0.0 "Cooked"는 MaruxOS 역사상 **두 번째 커널 빌드**이자 **첫 번째로 의도와 일치하는 진짜 빌드.** 그리고 오늘 이야기의 aarch64 트랙은 — **첫 번째 aarch64 진짜 빌드.**

### THE MOMENT
> 슬라이드에 광고 문구 `Linux 6.12 LTS`를 크게 띄우고, 그 위에 실제 파일명 `vmlinuz-6.7.4-maruxos`를 겹쳐 붉게 덮는다. 한 문장: **"검증 게이트가 없으면, 거짓이 인프라가 된다."**

### 화자 노트
- 이 막의 목적은 *공감 가는 실패*로 신뢰를 얻는 것. "AI가 완벽하다"가 아니라 "AI도 거짓말을 하고, 우리는 그걸 잡는 시스템을 만들었다"가 이 발표의 정직한 계약.
- 청중에게 던지는 약속: "오늘 보여줄 aarch64 트랙은, 이 실패에서 배운 **모든 게이트가 처음부터 작동한** 첫 프로젝트다."

## 2막 — 합성: 크로스툴체인에서 80패키지 에뮬빌드까지

### 슬라이드 비트
1. **무대 세팅.** 호스트 = x86_64 WSL2(Ubuntu). 타겟 = Raspberry Pi 4B 8GB(aarch64, BCM2711). x86_64 빌드와 **물리적으로 완전 분리된** 디렉토리 `~/MaruxOS-arm64/` — 폴더를 헷갈리면 5개월 환각이 재현된다는 걸 배웠으니까.
2. **커널: mainline 6.18.26 LTS.** 라즈베리파이 다운스트림 포크가 아니라 **mainline**. 통합 arm64 `defconfig` + Pi4 부팅 critical 드라이버 builtin 강제(`PCIE_BRCMSTB=y` 등). Image **47.7MB(50,022,912 B)**, `kernelrelease = 6.18.26-maruxos`. 32스레드로 약 9분.
3. **⭐ THE MOMENT — 게이트가 자기 자신을 재검증한다.** 커널 타르볼을 kernel.org에서 새로 받아 SHA256을 계산했다.
   - 결과: `53772f5d…0ec` == `config/lfs-versions.conf`의 canonical 값과 **완전 일치.**
   - 의미 3연타: ① 6.18.26은 실재하는 kernel.org 릴리즈다 ② x86_64 트랙이 박아둔 canonical SHA를 **독립적으로 재검증**했다 ③ **1.x의 6.7.4 환각과 정확히 정반대의 결과.** 게이트가 우리 자신의 메타데이터를 *생바이트로* 다시 확인했다.
4. **부트스트랩 철학 — "발판만 배포판, 배는 100% 소스."**
   - Ubuntu apt의 `aarch64-linux-gnu-gcc`(13.3.0)는 **오직 발판 스캐폴딩**으로만 쓴다. LFS가 호스트 gcc를 쓰는 것과 정확히 같은 패턴.
   - 최소 temp tools만 크로스컴파일 → `qemu-aarch64-static` binfmt로 **aarch64 chroot 진입** → 최종 유저랜드 전부를 chroot 안에서 **소스로(에뮬레이션 네이티브) 빌드.**
   - **쉬핑되는 OS = 100% from source, 배포판 바이너리 0개.** 무대 방어선: "LFS가 호스트 gcc를 쓰는 것과 동일."
5. **파이프라인(CLFS Ch4→Ch8).**
   - **Ch5** 크로스 툴체인 소스 빌드: binutils(2.41) → gcc pass1(13.2.0) → **우리 6.18.26 Linux API 헤더** → glibc 2.38 → libstdc++.
   - **Ch6** temp tools 17개(bash·coreutils·make·gawk·grep·sed…) + binutils/gcc pass2. 약 14분.
   - **Ch7** — 심장부 통과: `chroot` 진입 후 `uname -m` = **aarch64**, `bash 5.2.21 (aarch64)`, `gcc 13.2.0`이 전부 qemu로 실행. **cross → emulated 전환 성공.** (약 1h37m)
   - **Ch8** — 전체 시스템 **약 80패키지를 qemu 에뮬로 네이티브 빌드.** glibc FINAL·binutils FINAL·gcc FINAL·Python·perl 재빌드가 각 30분~2시간. 누적 **8~15시간, 밤샘급.** 청크(8-1~8-6) + `.done` 마커로 resumable하게 쪼갬.
6. **🎉 완성(2026-06-23 01:52).** MaruxOS 역사상 **첫 aarch64 from-scratch rootfs.**
   - 스모크 테스트(chroot): **self-hosting C 컴파일 ✓**, Python 3.12.2 ✓, **ko_KR.utf8 + Asia/Seoul ✓**, udevd/sysvinit ✓.
   - 규모: rootfs 4.6G, `/usr/bin` 584개, `.so` 244개.

### 화자 노트
- 이 막은 **장인정신의 스펙터클**. "AI가 소스에서 OS를 짓는다"는 게 슬로건이 아니라 실제 파이프라인이라는 걸 수치로 증명한다.
- 청중이 흔히 하는 오해를 선제 차단: "그거 그냥 크로스컴파일 아니냐?" → 아니다. 발판만 크로스, **최종 유저랜드는 qemu 에뮬 네이티브 빌드.** 이 구분이 정체성이다.

## 3막 — 사냥: 함정 5종 (각 1장)

> **연출**: 이 막은 리듬 게임처럼. 슬라이드마다 동일 템플릿 — **증상 → 원인 → 잡은 방법 → 교훈** 4칸. 관객이 "또 하나 잡았다"는 박자를 느끼게. 5장 연속.

### 함정 #1 — mainline에 `bcm2711_defconfig`는 없다
- **증상**: `make ... bcm2711_defconfig` → *"Can't find default configuration"*, `.config` 생성 실패.
- **원인**: `bcm2711_defconfig`는 **raspberrypi/linux 다운스트림 포크 전용.** mainline `arch/arm64/configs/`엔 `defconfig`·`hardening.config`·`virt.config` **셋뿐.** Pi4 지원은 통합 defconfig + DTS로.
- **근원**: 이전 세션(x86_64)의 정찰 노트가 "mainline `bcm2711_defconfig`로 Pi4 부팅 작동"이라 **미검증 단정.** Pi 빌드 0회 시점의 "작동" 주장 = 전형적 환각.
- **잡은 방법**: 가정을 안 믿고 mainline 소스를 실제로 받아 `ls arch/arm64/configs/` + `make defconfig` 실행 → 즉시 적발. **"AI 요약 박지 말고 raw로 확인"의 직접 승리.**
- **⭐ 발표 가치**: "다른 세션의 AI가 심은 미검증 가정을, 같은 AI가 raw 검증으로 잡았다." Hallucination Hunter 표본 — ARM64 트랙 1호.

### 함정 #2 — `update-binfmts` 부재 (그리고 휘발성)
- **증상**: qemu-user-static이 binfmt 자동등록을 못 함. Ubuntu 24.04에 `binfmt-support` 미설치, WSL엔 systemd-binfmt 자동실행 없음.
- **잡은/해소**: `/proc/sys/fs/binfmt_misc/register`에 수동 등록(`F` 플래그 = fix_binary, chroot 안전).
- **교훈(복선)**: 이 등록은 런타임(`/proc`) 상태라 **`wsl --shutdown`이나 슬립 시 소실된다.** — 이 한 줄이 4막 클라이맥스의 뇌관이 된다.

### 함정 #3 — 툴체인 버전 staging ≠ shipped
- **증상**: 풀 LFS북 결정 후 x86_64 소스 dir 재활용을 검토하다 **버전 불일치 적발.**
- **3중 불일치**:
  | 출처 | binutils | glibc | 신뢰도 |
  |------|----------|-------|--------|
  | x86_64 소스 dir (다운로드됨) | 2.42 | 2.39 | ⚠️ staging (빌드 안 됨) |
  | 설치된 `libc.so.6` | (2.41) | **2.38** | ✅ ground truth |
  | `lfs-versions.conf` (SSOT) | 2.41 | 2.38 | ✅ 일치 |
- **결정적 증거**: 설치된 `libc.so.6` → *"GNU C Library … release version 2.38"*. 다운로드된 2.39/2.42는 glibc 업그레이드 트랙용 **빌드 안 된 미끼(staging).**
- **⭐ 발표 가치 (Dementia Doctor)**: *"OS의 소스 staging(2.39)이 거짓 단서, 설치된 바이너리(2.38)가 진실."* **다운로드된 것 ≠ 빌드된 것 ≠ 메타데이터가 주장하는 것. ground truth는 언제나 가장 하류의 실물(installed artifact)뿐.**

### 함정 #4 — aarch64 gcc는 lp64를 `/lib64`로 보낸다
- **증상**: libstdc++가 `/usr/lib`가 아니라 **`/usr/lib64`**에 설치됨. glibc는 `/usr/lib` → gcc와 glibc의 lib 경로 분열.
- **원인**: `gcc/config/aarch64/t-aarch64-linux`의 `MULTILIB_OSDIRNAMES = mabi.lp64=../lib64…`. aarch64 gcc의 lp64 osdir 기본이 `../lib64`.
- **해소**: gcc 빌드 **전** sed로 osdir 교정(`lib64`→`lib`) + gcc/libstdc++ 재빌드. **이 sed는 pass2·final에도 매번 적용 필수.**
- **⭐ 발표 가치**: *"LFS 책은 x86_64 문서다. aarch64 포팅은 책의 암묵적 x86_64 가정 — lib64 sed, DTS, defconfig — 을 하나씩 들어내는 작업이다."* 함정 #1과 같은 계열: **문서의 아키텍처 편향.**

### 함정 #5 — 슬립이 binfmt를 죽인다 (→ 4막으로 넘어가는 다리)
- **증상 예고**: 장시간 qemu-chroot 빌드 도중 호스트가 슬립하면 binfmt+마운트가 소실되고, chroot 내 aarch64 실행이 끊긴다.
- **여기서 끊고**: "이게 어떻게 컴파일러 하나를 죽이고, 부트스트랩 전체를 무너뜨렸는지 — 다음 막."

### 화자 노트
- 5종을 두 계열로 묶어 착지: **(A) 문서의 아키텍처 편향**(#1, #4) — LFS/RPi 지식이 x86_64/포크 전제. **(B) 에뮬 빌드 인프라의 취약성**(#2, #5) + **(C) provenance 3중 불일치**(#3).
- 각 함정마다 "잡은 방법"이 전부 **raw 검증 / ground truth / 실측**이라는 걸 반복 각인 — 6막 Hunter 프레임의 사전 포석.

## 4막 — 붕괴와 부활: 슬립 연쇄장애 + 외과적 복원 (클라이맥스)

### 슬라이드 비트
1. **뇌관.** gcc final이 `make`를 완주(13:29)하고 `install`을 시작(13:31)한 직후, **약 4시간의 공백**(머신 슬립 추정). 그 사이 binfmt와 bind 마운트가 소실 → **install이 중간에 잘렸다.**
2. **연쇄 장애 3단(도미노).**
   - **① 깨진 `/usr/bin/gcc`**: 잘린 install이 pass2 gcc를 덮어썼는데 `cc1`/`cc1plus`가 미설치 → `gcc: cannot execute 'cc1'`.
   - **② 클린 재빌드도 실패(exit 77)**: gcc final의 configure가 conftest 컴파일에 그 **깨진 `/usr/bin/gcc`**를 사용 → *"C compiler cannot create executables."*
   - **③ 부트스트랩 부재**: 대체할 `/tools/bin/aarch64-lfs-linux-gnu-gcc`는 사실 **x86_64 크로스 바이너리**라 aarch64 chroot 안에서 실행 불가. → chroot 내 유일한 네이티브 gcc(pass2)가 죽었는데, 그걸 되살릴 컴파일러가 없다. **닭이 없어 달걀을 못 만든다.**
3. **외과적 복원(전체 롤백 회피).**
   - Ch7 스냅샷 백업(`lfs-ch7-snapshot.tar`)에서 **gcc 드라이버 17개 + `/usr/libexec/gcc` + `/usr/lib/gcc`만** 추출·복원.
   - **보존**: glibc final·binutils final·그 외 **22개 패키지는 손대지 않음.** 도미노를 되감되, 성한 것은 건드리지 않는다.
   - **검증**: gcc `aarch64-lfs-linux-gnu`, **C 컴파일 rc=42 ✓**, C++ ✓, glibc final 보존 ✓, ld 2.41 보존 ✓.
   - → 작동하는 부트스트랩 확보 → gcc final 클린 재빌드 configure 통과 → 완주.
4. **근원 조치(가역적).** 함정 #5의 뿌리 = 노트북 자동 슬립. `powercfg`로 AC 슬립/최대절전/뚜껑닫기 동작을 껐다. **되돌리는 명령까지 로그에 함께 박았다** — 빌드 생존을 위한 가역적 조치이자, 사용자 검토 대기 항목으로 큐에 올림.

### THE MOMENT
> 세 개의 붉은 도미노(gcc 깨짐 → 재빌드 exit 77 → 부트스트랩 부재)가 무너지는 애니메이션. 그리고 백업 스냅샷에서 **17개 드라이버만** 뽑아 끼우는 장면 위에 `rc=42`. 한 문장: **"전체를 롤백하지 않았다. 무너진 것만 되살렸다."**

### 화자 노트
- 이 막의 주제는 **엔지니어링 회복력**. 청중에게 남길 문장: **resumability · idempotency · snapshot = 장시간 에뮬 빌드의 생존 3종 세트.**
- 정직 포인트: 이건 AI의 실수가 아니라 **호스트 OS의 전원 관리가 게스트 빌드를 끊은** 인프라 사고다. 하지만 복구를 설계한 것도, `.done` 마커로 멱등하게 만들어 둔 것도 시스템이었다.
- `rc=42`는 이 프로젝트의 사인. 스모크 테스트가 42를 반환하도록 심어둔 이스터에그 — "동작 증거"의 서명으로 무대에서 한 번 짚어주면 좋다.

## 5막 — 브링업: 실기기 앞에서 (관측 불능 → 클린부팅 → 한글 데스크톱)

> **✅ 갱신(2026-07-23) — 이 막은 이제 승리 서사다.** 원래 이 막은 "발표 당일까지 미해결인 라이브 프론티어"로 설계됐다(아래 인용 보존). 실제로는 **2026-07-08 부팅 해결 → 그래픽 데스크톱(v7.1) → 한글 입력(v10)** 까지 완성됐다. 이제 무대에서 **실물 Pi 4B가 한글을 타이핑하는 장면**을 보여줄 수 있다. 단, *반전의 힘*은 유지한다: 5일간 "부팅 실패"로 믿은 것이 실은 **관측 불능(죽은 시리얼 어댑터)**이었다는 것.
>
> **(원래 정직 원칙 — 역사 보존)**: *"로그 기준(2026-07-05) 실기기 부팅은 미해결/진행중. 무대에서 '파이가 데스크톱까지 떴다'고 말하지 않는다."* — 이 원칙은 2026-07-05 시점엔 옳았고, 결국 **데스크톱은 실제로 떴다.** 성공을 지어내지 말라는 원칙은 그대로 유효하다(부록 B는 이제 시나리오 S1으로 확정).

### 슬라이드 비트
1. **소프트웨어와 하드웨어는 다른 게임.** rootfs·부팅 이미지는 완성됐다(`output/MaruxOS-2.0.0-arm64.img.xz`, v2 약 1.02GB). SD 이미지: p1 FAT32 512M(boot) + p2 ext4(root). 부팅 체인: EEPROM → `start4.elf` → `config.txt` → `kernel8.img` + dtb → 커널 → sysvinit → `marux login:`. **U-Boot도 GRUB도 없다.**
2. **증상.** 실기기에서: 무지개 화면 0.1초 → 블랙 + **초록 LED 2회 반복 깜빡** + 시리얼 무출력.
3. **환각 없는 진단 4단.**
   - **① SD 내용 = 완벽.** PowerShell로 부트 파티션 6개 파일의 정확한 크기·FAT32 검증. "잘못 구운 것"이 아니다.
   - **② LED 코드 = 공식 표로 확인.** 기억으로 박지 않고 검색해 공식 표 대조 → 반복 깜빡임 = **펌웨어가 부트 파티션/파일을 못 읽음.**
   - **③ `config.txt` 한글 주석 → mojibake 발견.** Pi의 원시 파서가 비ASCII에 취약 → **순수 ASCII로 교체(BOM 없음).** *"비ASCII가 Pi 부트로더를 죽인다"* 함정 추가 적발·수정.
   - **④ 결정적 격리.** 공식 **Raspberry Pi OS를 같은 SD에 구워 부팅 → 정상.** → **SD카드·리더·Pi·EEPROM 전부 정상, 범인은 우리 이미지로 확정.** (추측이 아니라 대조 실험으로.)
4. **🔒 사용자 절대 원칙 — 정체성 사수.** *"다른 OS 참고한답시고 이 프젝을 라파 그 자체로 만들면 안 된다."*
   - 참조·차용 허용: **Broadcom 펌웨어(`start4.elf` = GPU 펌웨어 = BIOS급, OS 아님)·overlays·config 형식.**
   - 100% 우리 것 유지: **커널(우리 mainline 6.18.26-maruxos)·rootfs(우리 from-scratch)·dtb(우리 mainline).**
   - 슬로건: **"남의 부트 메커니즘은 배우되, 정체성(커널·rootfs)은 사수한다."**
5. **⭐ THE REVERSAL — 범인은 이미지가 아니었다.** 앞의 4단 진단은 완벽한 방법론이었지만, 그 결론("범인=우리 이미지")이 함정이었다. 우리는 용의자를 둘(FAT 구조 vs 50MB 커널)로 좁혔는데 — **둘 다 무죄였다.** 진범은 훨씬 앞단에 있었다: **계측기 자체가 죽어 있었다.**
   - **죽어가던 FT232RL 시리얼 어댑터.** v1~v4 전부 "장님 디버깅"(LED만 보고 추측)이었다. 시리얼이 무출력이었던 건 부팅이 안 돼서가 아니라 **어댑터가 단선**이라서. 게다가 이 케이블은 **흰=TX/초=RX 라벨** → 배선이 반대로 꽂혀 있었다.
   - 새 FT232RL + **흰↔초 배선 스왑** + `enable_uart=1` → 처음으로 시리얼이 살아났다. RPi OS가 `raspberrypi login:`까지 **30,378바이트** 쏟아냈다. 관측 채널 복구.
   - **드러난 진실**: 우리 커널은 *처음부터* 완전 부팅하고 있었다 — 4-CPU SMP·PCIe·USB·eth0·ext4 마운트·`/sbin/init` 실행 전부. 펌웨어는 50MB 커널을 완벽히 로드해 핸드오프했다. **"짧2 LED"는 부팅 실패가 아니었다.** 유저스페이스는 안 보이는 tty1 더미 콘솔로 새고 있었을 뿐.
6. **THE FIX — 콘솔 라우팅 + rootfs 4종.** cmdline **`console=ttyS0,115200`를 맨 뒤로** → `/dev/console`이 시리얼에 물림 → init/rc가 처음으로 드러남. 이어서 경미한 rootfs 설정 4종(`/bin/udevadm` 심링크·fstab `/dev/shm`+cgroup·S70console·S10sysklogd)이 rc마다 "Press Enter"를 유발한 걸 픽스. → **v6: 무인 클린부팅(FAIL 0) → `marux login:`.** 그리고 실물 Pi 쉘에서 **gcc 13.2.0가 C를 컴파일+실행(self-hosting).**
7. **🎉 THE TRIUMPH — 블랙 화면에서 한글 데스크톱까지.**
   - **HDMI 부활**: 블랙 화면도 부팅 실패가 아니라 디스플레이 드라이버 부재(dummy console)였다 → 커널 **VC4/V3D `=y`** + `max_framebuffers=2`(mainline dtb라 dtoverlay 불요) → 실물 1080p 콘솔(Stage 5a).
   - **그래픽 데스크톱(v7.1, 2026-07-17/18)**: X.org 21.1.11 + mesa 24(vc4/v3d) + openbox+tint2+xterm이 **실물 HDMI에 렌더링**. 마우스 더블클릭으로 xterm 실행, 키보드 입력(libinput), **한글 표시**(18x18ko 비트맵 폰트).
   - **x86 패리티(v8, 2026-07-20)**: feh 배경화면·mc·바탕화면 아이콘·우클릭 풀메뉴·Win 키바인드.
   - **🇰🇷 한글 입력(v10, 2026-07-23)**: ibus-hangul XIM. 사용자가 실물 Pi 4B의 xterm에서 **`Shift+Space` → `gksrmf` → `한글`.** = AI가 맨바닥부터 합성한 OS가 실물 라즈베리파이에서 한국어를 타이핑한다.
   - **🌐 완전한 데스크톱(v11~v16, 2026-07-25~29)**: gtk+-3.24.41 + **Firefox ESR(공식 aarch64 한국어 빌드) + gtk3 한글 입력**(v11) → **유선 네트워크 out-of-box + NTP("1970 시계" 완치) → 실물 Pi에서 한글 웹서핑**(v12, 실기기 검증) → **Plank dock을 소스에서 빌드**(Vala 컴파일러 부트스트랩 = **자체 valac 보유**, v14) → picom + "Marux" 반투명 유리 테마(v15~v16). 현재 이미지 = **v16**.

### THE MOMENT
> **실물 Pi 4B 화면에 `한글`이 타이핑되는 라이브(또는 영상).** 그 위에 5일 전의 "짧2 LED 깜빡임"을 작게 겹쳐 붉게 지운다. 한 문장: **"우리가 5일간 '고장'이라 부른 건, 눈을 감고 있었던 것뿐이다. 눈을 뜨자, OS는 처음부터 살아 있었다 — 그리고 이제 한국어를 말한다."**

### 화자 노트
- 이 막의 힘은 **반전**이다. FAT·커널·펌웨어를 모두 피고석에 세운 정교한 대조 실험 끝에, 진범이 **3달러짜리 죽은 USB 어댑터**였다는 것. 교훈: **"안 보이는 것 ≠ 안 되는 것. 진단은 계측기부터 의심하라."**
- 5막이 4막의 회복력 서사와 짝을 이룬다: 4막은 *에뮬 빌드*의 브링업, 5막은 *실리콘*의 브링업. 둘 다 "환각 없이, 실측으로." 그리고 5막은 4막과 달리 **완결된 승리**로 끝난다(한글 데스크톱).
- 정직 포인트: 대조 실험 방법론(RPi OS 격리)은 여전히 자랑거리다 — 그게 **하드웨어·펌웨어·FAT를 무죄로 좁혀줬기에**, 남은 유일한 변수(관측 채널)로 시선이 갈 수 있었다. 방법론이 틀린 게 아니라, 방법론이 마지막 한 칸까지 밀어붙였다.

## 6막 — 프레임: Hallucination Hunter / Dementia Doctor / Final Decider

> **연출**: 앞 5막의 사건들을 세 개의 렌즈로 재수납. 새 정보가 아니라 **재해석.** 발표의 주제 착지.

### ① Hallucination Hunter — 거짓말을 잡는 시스템
- **증거**: 함정 #1(다른 세션 AI의 미검증 가정을 raw 검증으로 적발), **SHA 게이트가 자기 자신의 메타데이터를 생바이트로 재검증**(2막 ⭐), LED 코드를 기억이 아니라 공식 표로 확인(5막).
- **명제**: *"AI가 환각한다는 게 문제가 아니다. 환각이 검증 없이 인프라가 되는 게 문제다."* 1.x의 6.7.4가 5개월(약 1년) 살아남은 이유 = 게이트 부재. ARM64 트랙 = **첫날부터 모든 단일진실값에 게이트가 붙은** 첫 프로젝트.

### ② Dementia Doctor — 프로젝트가 자기 역사를 잊지 않게
- **증거**: 함정 #3(staging 2.39가 거짓 단서, 설치된 2.38이 진실 — **ground truth는 산출물뿐**), 그리고 **모든 함정·결정·실패를 두 로그(`Kernel-Update-Log.md` / `ARM64-Update-Log.md`)에 빠짐없이 박제**하는 규율.
- **명제**: *"LLM은 세션이 끝나면 기억을 잃는다. 그래서 프로젝트의 기억을 외장화한다 — 로그·게이트·SSOT가 AI의 해마다."* 6.7.4가 살아남은 두 번째 이유도 "표면이 깔끔해 보여서" = **기억의 부재.** Doctor의 처방 = 실측을 항상 가장 하류의 실물에서.

### ③ Final Decider — AI는 합성한다, 인간이 결정한다
- **증거**: Phase 1→2 순서 고정("Phase 2 직진 금지"), **풀 커널·풀 LFS북** 결정("내 몸 갈아넣으면 그만"), **"라파 그 자체가 되지 마라"** 정체성 원칙, 슬립방지 호스트 변경을 **가역적으로 선적용하되 사용자 검토 대기**로 큐잉.
- **명제**: *"AI가 aarch64 OS 전체를 합성했지만, 무엇을 지킬지·어디서 멈출지·무엇이 우리다움인지는 인간이 결정했다."* 17세 개발자가 최종 결정권자.

### 클로징 (착지)
1. **한 화면 요약**: 크로스툴체인 → qemu-chroot → **약 80패키지 에뮬 빌드** → 함정 **5종 전부 적발** → 슬립 연쇄장애를 **가역성으로 복구** → "5일 부팅 실패"의 진범(죽은 시리얼)을 밝혀 **실물 Pi 클린부팅** → HDMI → 그래픽 데스크톱 → **한글 입력** → **한글 웹서핑(Firefox+유선 네트워크)** → **Plank 유리 데스크톱(자체 valac로 소스빌드)**.
2. **주제 문장(발표 전체를 관통)**:
   > **"검증 게이트가 없으면, 거짓이 인프라가 된다. 그래서 우리는 OS를 짓기 전에, OS의 진실을 강제하는 시스템부터 지었다."**
3. **정체성 재천명**: World's First 100% LLM OS · Public Domain · 오픈소스 환원. **AI가 합성하고, 게이트가 검증하고, 인간이 결정한다.**
4. **(당일 상태 반영)** 실기기 데모 슬라이드 — [부록 B]는 이제 **시나리오 S1(부팅 성공 + 한글 데스크톱)로 확정.** 실물 Pi 4B에서 `Shift+Space` → `한글` 타이핑 라이브/영상으로 마무리. 클로징: **"환각에서 시작해, 실리콘 위에서 한국어로 끝났다."**

### Pull quote (엔딩)
> *"1.x는 5개월 동안 자기가 6.12라고 믿었다. 2.0.0 aarch64는, 태어난 첫날 자기 SHA256을 스스로 다시 세어봤다. 그 차이가 이 발표의 전부다."*
